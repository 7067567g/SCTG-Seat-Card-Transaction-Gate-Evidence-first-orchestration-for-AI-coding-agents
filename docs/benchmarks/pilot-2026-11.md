# Raw agent vs SCTG: a same-task pilot

> Question: does SCTG make a small coding task faster?

**Short answer: no.** In this pilot, SCTG added 25–97% wall-clock overhead.
Its value was not latency; it was auditability.

## Method

- Same model: `deepseek/deepseek-flash`.
- Same seed repository and same task prompt for both arms.
- Raw arm: one OpenCode prompt, no SCTG.
- SCTG arm: one task card + four gates (`g0_schema`, `g1_scope`,
  `g2_evidence`, `g3_command`).
- 2–3 trials per task.
- Hidden semantic checks were run after the agent stopped.

## Tasks

| Task | What changed |
|---|---|
| multiply | add `multiply()` with type validation |
| bugfix | fix `mean()` and handle empty input |
| refactor | extract a shared whitespace-normalization helper |
| security | reject path traversal in `safe_join()` |

## Result

| Task | Raw median | SCTG median | SCTG overhead | Hidden tests | Gates |
|---|---:|---:|---:|---|---|
| multiply | 28.175s | 35.141s | +24.7% | both PASS | PASS |
| bugfix | 13.160s | 25.875s | +96.6% | both PASS | PASS |
| refactor | 19.702s | 32.451s | +64.7% | both PASS | PASS |
| security | 24.523s | 45.600s | +85.9% | both PASS | PASS |
| **overall median** | **22.617s** | **35.141s** | **+55.4%** | both PASS | PASS |

## What SCTG added

For every SCTG run:

- a rendered task card with `card_hash`;
- a submission with changed/produced/evidence/command fields;
- a baseline snapshot;
- a structured gate result;
- a test-command log;
- an acceptance ledger row;
- a scope check proving writes stayed inside the declared boundary.

The raw arm had none of these as first-class artifacts. The transcript and diff
were the only record.

## Interpretation

SCTG is **not a speed optimization for small tasks**. On a one-file edit, a
strong raw coding agent is usually faster.

SCTG is useful when the cost of **manual verification, scope drift, missing
evidence, or unreviewed retries** is higher than the gate overhead:

- multi-file changes;
- security-sensitive changes;
- multi-round work;
- changes that need an auditable acceptance record;
- workflows where a different seat must review the result.

This pilot does not prove that SCTG is faster on large tasks. It does show that
the overhead is measurable and that the extra artifacts are real.
